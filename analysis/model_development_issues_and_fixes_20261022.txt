1. 전체 흐름과 핵심 전환
=======================

초기 목표는 ring을 하나의 큰 seed로 다뤄 Cartesian 생성 중 고리 붕괴를
줄이는 것이었다. 하지만 고리 geometry를 보존해도 원자 공유, 결합, 수소,
치환기 attachment가 함께 일치하지 않으면 유효한 분자가 되지 않았다.

그래서 자유 원자를 추가한 hybrid, ring-cell membership을 가진 FPA,
scaffold/junction 계층형 모델, atom/bond joint DDPM, tree+closure까지
표현을 바꿨다. 이 과정에서 단순히 loss/prior/projection을 더하는 것으로
전체 분자의 결합 일관성이 보장되지 않는다는 점이 반복 확인됐다.

이후 원본 MolGuidance를 별도 baseline으로 도입해 자체 모델과 비교했다.
현재는 heavy-atom Cartesian endpoint flow와 masked categorical CTMC를
결합한 모델을 사용한다. 일반적인 Gaussian epsilon-prediction DDPM과는 다르다.

현재 HP1KG와 STGG는 같은 Stage8 아키텍처/학습 원리를 쓰는 별도 실험이다.
두 모델이 다른 신경망 설계인 것은 아니지만 DB, 원소/state 어휘, 조건,
분자 크기, 좌표 출처, 학습량 및 가중치는 서로 다르다.


2. 초기 QCDGE·ring/hybrid·FPA에서 발생한 문제
==========================================

2.1. NaN, 빈 원자 집합, padding 오염
문제:
  ringless 또는 free-atom이 없는 사례, 전부 masked된 attention,
  유효 항목이 없는 loss에서 NaN이 발생할 수 있었다. padded relation이
  실제 ring hidden을 바꾸는 오류도 감사 과정에서 확인됐다.
수정:
  node/pair/cross mask 분리, 빈 집합의 loss=0 처리, 유효 ring이 있는
  graph에만 cross-attention 적용, 유한성 검사·분모 하한 등의 방어를 추가했다.
  현재는 주 배치를 DGL 가변 크기 graph로 처리하며, FAKE와 padding을 구분한다.
판정:
  [수정·검증] 해당 경로를 방어했지만 모든 NaN의 원인이 같지는 않다.
  실제 Stage8에서는 별개의 FP32 log-likelihood 문제가 다시 발생했다(7.1).

2.2. 고리만 생성되고 비고리 치환기가 빈약함
문제:
  ring 중심 표현만으로는 비고리 원자와 다원자 치환기의 연결을 충분히
  생성하지 못했다. ring seed 수를 키우면 유효율이 급격히 나빠졌다.
수정:
  hybrid에 free-heavy-atom 좌표/종류/전하/내부 bond/attachment/port/count를
  추가했다. 이후 모든 heavy atom을 명시하는 template-free 표현으로 전환했다.
판정:
  [실험/대체] 표현 범위는 넓혔지만 attachment·공유 원자·bond의 독립 예측
  문제까지 자동 해결하지는 못했다. 현재 Stage8는 ring-template 모델이 아니다.

2.3. 템플릿 의존성과 fused/spiro/T형 polyaromatic 표현
문제:
  DB에서 본 완성 ring template만 사용하면 새 heteroatom 배치와 복잡한
  polyaromatic 조합이 제한됐다. 반지름 하나로 화학 identity를 정할 수도 없다.
수정:
  고리의 geometry와 원자 chemistry를 분리하고 ordered membership,
  junction/shared-atom mapping, unknown-size ring 보존 경로를 도입했다.
  FPA의 cell은 보조 기하 단위이며 최종 분자는 atom graph로 정의하도록 했다.
판정:
  [실험/대체] 선형뿐 아니라 분기·T형·fused/spiro를 표현할 수 있는 것과
  그 구조를 실제로 생성할 수 있는 것은 별개였다.

2.4. encoder/decoder에서 원본 분자가 달라짐
문제:
  heavy adjacency나 ring membership이 같아도 H, radical, formal charge,
  aromatic/Kekulé bond가 다르면 RDKit 기준으로 다른 분자가 된다.
  좌표 거리로 ring edge를 다시 추정하거나 canonical SMILES atom order를
  저장 좌표 순서와 섞는 경로도 복원을 깨뜨렸다.
수정:
  H/charge/radical sidecar, source graph↔coordinate mapping, explicit ordered
  bond/membership를 저장하고 RDKit canonical non-stereo identity를 검사했다.
  mapping 실패와 multi-fragment는 별도로 식별·필터링하며 예외를 기록했다.
판정:
  [수정·검증/잔존] 초기 전체 QCDGE FPA 감사는 완전한 100%가 아니었다.
  당시 133,704개에서 bond/membership tensor는 100%였지만,
  parseable reference identity는 131,728/131,731이었다.
  reference parse 불가 1,973개, identity mismatch 3개,
  projection exception 14개, RDKit reconstruction exception 54개가 남았다.
  이후 HP1KG joint codec의 1,581/1,581과 다른 DB·다른 단계의 검사다.

2.5. 계층형 scaffold 모델에 빠져 있던 학습 경로
문제:
  감사 당시 slot bond head가 loss에 연결되지 않았고, 치환기 내부 bond 표현,
  relation↔junction consistency, 공유 원자 chemistry union,
  validation/resume/production sampler 등이 불완전했다.
  clean slot 좌표를 chemistry가 보는 train–sample mismatch도 지적됐다.
대응:
  단순 prototype의 codec 통과를 전체 모델 완성으로 취급하지 않고,
  atom/charge/Kekulé bond/coordinate를 공동 생성하는 baseline으로 문제를 분리했다.
판정:
  [실험/대체] 이 prototype의 모든 항목이 최신 경로에 그대로 수정·상속됐다는
  뜻은 아니다. 현 모델은 별도의 MolGuidance 기반 구현이다.


3. 자체 joint DDPM V4~V8 및 tree/closure 실험의 문제
=================================================

3.1. forward/reverse 확률 과정의 불일치
문제:
  초기 categorical reverse가 정식 posterior sampling과 달랐고,
  좌표 terminal prior와 training schedule이 일치하지 않는 경로가 있었다.
  reverse 중간 hard clipping/projection도 원래 forward kernel에 없었다.
수정:
  empirical-marginal D3PM posterior, epsilon-DDPM posterior,
  terminal alpha-bar 검사, 중간 hard projection 제거 및 실패 진단을 도입했다.
검증 기록:
  V8 posterior brute-force Bayes 최대 오차 3.58e-7,
  Cartesian t=0 oracle 오차 1.55e-6, terminal alpha-bar 2.93e-6.
판정:
  [수정·검증] 수식 경로 검사다. 높은 생성 성공률을 보장하지 않았다.

3.2. edge 존재/type/aromatic의 독립 head 충돌
문제:
  no-edge인데 bond type이 있거나 aromatic flag와 실제 결합이 어긋나는
  독립 출력의 조합이 발생했다. NONE class 불균형도 컸다.
수정:
  한때 existence/type 분리를 실험했으나, V7/V8에서는 joint edge state로
  통합했다. 현재 Stage8도 하나의 NONE/S/D/T softmax를 사용하며
  edge-existence 보조 loss는 그 softmax에서 유도한다. 별도 독립 head가 아니다.
판정:
  [부분 개선] 모순된 state 조합은 줄였지만 원자 state와 전체 bond를
  동시에 샘플링했을 때의 원자가 위반은 여전히 가능하다.

3.3. 잘못된 ring target, tree gauge와 과도한 다각고리
문제:
  canonical SMILES 재파싱 뒤 index를 재사용해 실제 non-bond에 ring target을
  붙이는 오류가 있었다. V8 감사에서 train 1,264개 중 935개에 해당 오류가
  확인됐다. 특정 spanning tree 강제와 fundamental cycle을 실제 최소 고리로
  취급한 것도 fused/bridged 구조의 target을 왜곡했다.
수정:
  stored atom/bond 순서로 target 생성, cyclic/aromatic subset assertion,
  edge 제거 후 shortest replacement path, minimum-cycle-basis 통계,
  single-commodity flow connectivity, train-only topology prior를 도입했다.
  cycle-rank/edge-count 중복, 부정확한 bridgehead·soft-cycle surrogate를 정리했다.
판정:
  [수정·검증/부분 개선] 잘못된 감독 신호는 수정했지만 정상 ring topology의
  높은 생성 확률까지 확보하지 못했다. 이러한 V8 prior를 현재 Stage8가
  모두 그대로 사용하는 것은 아니다.

3.4. aromatic class 강제와 유효 Kekulé 배치의 차이
문제:
  모든 perimeter edge를 aromatic class로 맞추게 하거나 특정 S/D phase만
  정답으로 강제하면 유효한 공명 표현이 서로 벌점을 받았다.
  heteroatom/전하/P/S/비표준 perimeter를 benzene 규칙으로 처리하는 것도 오류였다.
수정:
  Kekulé S/D 중심 표현, resonance-invariant incidence,
  hetero/charge-aware 전역 assignment, RDKit 전역 sanitization을 도입했다.
  지수적 cycle-pattern 열거 대신 matching/DP 계열을 사용했다.
  [nH+]를 neutral [nH]와 같이 취급하던 MILP 특례를 제거했다.
검증 기록:
  V8 flow-MILP oracle의 초기 18건 실패를 수정한 뒤 1,581/1,581 복원.
판정:
  [수정·검증/부분 개선] 정답 endpoint를 넣었을 때의 복원 검사이지,
  noisy model prediction에서 유효한 assignment가 자주 나온다는 증거는 아니다.

3.5. loss는 감소하지만 단원자·단순 구조만 생존
문제:
  atom/cell/membership/bond 등 여러 marginal의 우연한 일치를 요구하고,
  마지막 projection이 대부분을 탈락시키는 구조였다.
  전체 val loss와 생성 유효율의 관계가 약했다.
실제 예:
  V8 e126, 1,000개 요청에서 raw RDKit valid 5, raw joint valid 1,
  projection valid 5, chemical-clean 3, 5·6원 고리 비율 0%,
  generated bond Z-RMS 약 39.0이었다.
대응:
  raw/projection/clean/geometry/condition 지표를 분리하고,
  tree+cycle-closure V9를 별도 구현·실험했다. 이후 원본 MolGuidance를
  가져와 DB adapter만 바꾸는 baseline으로 자체 구조의 영향을 분리했다.
판정:
  [실험/대체] V9 설계와 oracle 검증도 일반적인 성능 향상 증명이 아니다.
  현재 사용 경로는 V9가 아니며, 'diffusion 자체가 불가능하다'는 결론도 아니다.


4. MolGuidance baseline에서 발견한 학습·가이던스 문제
===================================================

4.1. categorical loss broadcasting
문제:
  categorical CE [N]와 time weight [N,1]를 곱하면 [N,N] outer product가 된다.
  scalar mean은 mean(CE) * mean(weight)이며 mean(weight_i * CE_i)와 다르다.
대응은 두 가지를 구분했다:
  (a) 원본 보존: outer product를 만들지 않고 mean(CE)*mean(weight)를 명시해
      원본 loss/gradient를 대수적으로 유지한다. 메모리와 모호성을 줄이는 수정이다.
  (b) 목적함수 변경: sample-aligned 또는 masked-only weighted CE를 선택한다.
      Stage7/8 기본은 sum(mask_i*w_i*CE_i)/max(sum(mask_i),1)이다.
  legacy/aligned/masked_weighted/masked_unweighted 대조 설정과 회귀 검사를 추가했다.
판정:
  [수정·검증] casting(dtype) 오류가 아니라 shape/reduction 의미의 문제였다.
  (a)는 학습 목적을 바꾸지 않고, (b)는 바꾼다. 이전 성능이 더 좋았다는 것만으로
  원저자의 의도나 (b)의 보편적 우월성을 판정할 수 없다.
  서로 다른 loss 정의의 절대값·감소 배수를 성능 향상으로 읽으면 안 된다.

4.2. EMA teacher가 실제 optimizer update를 따라가지 않음
문제:
  EMA가 존재해도 올바른 optimizer lifecycle에 연결되지 않으면 teacher가
  갱신되지 않거나 시점이 어긋난다.
수정:
  optimizer_step 뒤 EMA 갱신, buffer 복사, teacher eval 유지,
  teacher 전용 property embedder 사용을 연결했다.
  실제 1 optimizer step 뒤 EMA weight 변화와 기대값을 검사하는 unit test를 추가했다.
판정:
  [수정·검증] 실행 결함 수정이다. EMA만으로 조건 제어 성능이 보장되지는 않는다.

4.3. MG edge guidance의 graph offset 오류
문제:
  node slice 길이 n을 upper-triangle edge packing에도 사용하면
  서로 다른 분자의 guidance가 섞일 수 있다.
수정:
  node는 n, 무방향 edge는 n(n-1)/2로 각각 offset을 계산한다.
  [3,5,2] 노드 배치에서 edge slice가 [0:3], [3:13], [13:14]임을 검증했다.
판정:
  [수정·검증] EMA와 함께 독립 수정·커밋된 항목이다(b4518a7).

4.4. categorical MG target과 CFG rate 처리
문제:
  hard argmax teacher가 분포 정보를 제거하고, scale convention과 범위,
  coordinate/graph time, probability/rate guidance 경로가 일관되지 않았다.
수정:
  detached soft teacher target, scale 0~2 계약, 1=conditional convention,
  graph time cutoff, unsupported-state 차단을 도입했다.
  선택적 rate-matrix 경로에서는 mask-star frozen generator transition을
  matrix exponential과 대조하고 단순 I+dtQ 원소 clipping을 제거했다.
판정:
  [수정·검증/잔존] 자체 probability-space distillation 확장이다.
  원 논문의 정리가 자동으로 성립한다고 주장하지 않는다.
  현재 HP1KG/STGG 장기학습은 CFG이며 MG 모델을 학습 중인 것이 아니다.

4.5. '조건 반영률'과 실제 물성 정확도의 혼동
문제:
  condition shuffle gain, CFG 출력 차이, loss 기여도를 물리적 목표 달성률로
  해석할 위험이 있었다. S1/EST 극단 구간에서는 DB 분포 편향도 컸다.
수정:
  조건 shuffle·null/conditional 비교, 동일 seed/count의 CFG0/1/2 비교,
  train DB 분위별 평가와 독립 XTB/STDA를 추가했다.
  scalar raw eV → train normalization → property embedding 계약을 명시했다.
판정:
  [부분 개선/잔존] 조건 민감도와 실제 물성 적중률은 별개다.
  residual scale 0.5는 '50% 반영', shuffle gain 0.08은 '8% 기여'가 아니다.
  현재 CFG1은 조건부 모델 그대로, CFG0은 조건 미사용 기준이다.

4.6. condition dropout만 있고 일반 regularization은 부족함
문제:
  CFG용 condition dropout을 hidden/message dropout으로 혼동했다.
  작은 DB에 큰 모델, 매우 작은 weight decay, 장기학습이 과적합 위험을 키웠다.
수정:
  실제 GVP dropout 0.05, weight decay 1e-5, scalar/edge 128/64,
  4 update block, LR 2.8e-4의 작은 Stage8 모델을 도입했다.
판정:
  [구현 검증/성능 미확정] dropout은 과적합을 반드시 막는 장치가 아니다.
  각 변경의 인과적 효과는 같은 step 예산/여러 training seed의 ablation이 필요하다.


5. 수소·입력 좌표·DB 수정
========================

5.1. 수소를 RDKit implicit valence에 맡겨 radical/화학 상태가 달라짐
문제:
  heavy graph를 그릴 수 있어도 모델이 H 상태를 지정하지 않으면 RDKit의
  보완 규칙에 따라 의미가 달라지거나 radical/전하 구조가 남는다.
수정 순서:
  H0~H3 categorical head 추가 → element/charge/H를 하나의 joint state로 통합.
  decoder에서 SetNumExplicitHs 및 SetNoImplicit(True), unresolved mask 거부.
현재:
  H는 학습에 포함된다. 그러나 H를 별도 graph node/Cartesian 좌표로 생성하지 않는다.
  별도 radical output head도 없다. 생성 그래프의 radical 여부를 RDKit으로 판정한다.
판정:
  [수정·검증/잔존] H를 포함해도 atom/H와 bond 샘플이 안 맞으면 radical이 생긴다.
  e3911 valid 865개 중 radical 포함 144개가 남아 있다.

5.2. aromatic bond schema의 정보 손실
문제:
  초기 H-count codec은 1,580/1,581 identity였다. 비표준 aromatic triple-bond
  record를 aromatic 단일 class로 저장해 원본 정보를 잃었다.
수정:
  element/formal-charge/H joint state와 NONE/S/D/T Kekulé bond로 전환했다.
  전체 분자의 RDKit identity를 train/val/test에서 각각 확인했다.
판정:
  [수정·검증] 현재 HP1KG pure codec은 1,581/1,581이다.
  stereochemistry 보존까지 검증했다는 뜻은 아니며 현재 표현 범위에서 제외된다.

5.3. CSV에 XYZ가 없다는 사실을 DB 전체에 3D가 없다는 뜻으로 해석함
문제:
  초기 HP1KG adapter는 SMILES로 ETKDG 좌표를 만들었다.
  공식 repository의 개별 optimized XYZ를 별도로 받는 경로가 확인되지 않았었다.
수정:
  공식 파일을 다운로드하고 checksum·분자식·원자 수·좌표 단위를 검증했다.
  XYZ와 S1/T1을 HDF5로 묶고 모델용 heavy-atom mapping을 재구성했다.
  NEFPAR의 ORCA out 최종 좌표와 XYZ가 0 Å 차이임을 확인했다.
판정:
  [수정·검증] HP1KG 현재 좌표는 공식 S0 B3LYP/6-31G* 최적화 기하이며,
  excited-state label은 그 기하의 vertical NEVPT2 값이다.
  S1/T1 각각 최적화된 excited-state geometry가 아니다.

5.4. 공식 XYZ와 trusted SMILES의 일부 H/결합 정의 차이
문제:
  checksum과 인덱스가 맞아도 공식 geometry와 trusted graph가 완전히
  같은 bonding/protonation 상태인지는 별도 문제다.
검증 결과:
  heavy graph+H exact 1,516개, element graph exact지만 H mismatch 59개,
  edge 정의 차이 6개. 전체 H-attachment mismatch는 61개로 기록됐다.
  edge 예외 ID: SEFVEE, TIPTOB, AFAFAP, SODBIW, HONFIA, ICAHUQ.
대응:
  예외를 따로 기록하고 trusted graph와 official XYZ를 보존했다.
  거리를 보고 기존 graph를 조용히 바꾸지 않았다.
판정:
  [잔존] 현재 1,581개 전체 사용과 codec100%는 이 graph-geometry 차이를
  물리적으로 해결했다는 뜻이 아니다. 데이터 제외/재정의는 별도 결정이 필요하다.

5.5. DB 변경·원소 어휘·조건 정의 혼동
문제:
  QCDGE에서는 미관찰 원소가 나오거나, 다른 DB로 바뀐 뒤 이전 조건/vocab,
  split/normalization을 재사용할 위험이 있었다.
수정:
  data-derived vocabulary, train-only generative support, 데이터별 변환기,
  manifest/hash, 새로운 run/checkpoint를 사용했다.
현재 구분:
  HP1KG: 1,581개(train1264/val158/test159), 12원소, EST=S1-T1.
  STGG: 기존 첫100k 중 cross-split 중복1개 제거, 99,999개
        (train80000/val10000/test9999), 8원소, S1=1239.84193/wavelength(nm).
  STGG에는 T1/EST 학습 label이 없고, 이번 실험은 전체2.9M 학습이 아니다.
  STGG 좌표는 기존 ETKDG/force-field conformer이며 HP1KG 공식 XYZ와 다르다.
판정:
  [수정·검증/잔존] STGG와 HP1KG의 차이를 aromaticity 하나의 인과효과로
  해석할 수 없다. STGG novelty도 사용한99,999개 기준이며 full2.9M 비교가 아니다.


6. 최신 Stage7/8의 구조·수학 정합성 수정
======================================

6.1. 여러 head의 평균값이 맞아도 discrete graph는 무효
문제:
  benzene 각 edge가 S/D=0.5이면 expected double degree는 맞지만
  독립 표본에서 두 alternating pattern이 나올 확률은 2/64=3.125%에 불과하다.
수정:
  joint atom state, atom/H/charge↔bond chemistry feedback,
  분포 기반 valence/charge compatibility DP를 추가했다.
  DP는 overflow 질량을 버리지 않고 이미 공개된 CTMC 항목은 observed one-hot을 쓴다.
판정:
  [부분 개선] 국소/분포 loss도 전체 discrete assignment의 유효성을 보장하지 않는다.

6.2. 한 가지 Kekulé phase에 과도하게 종속
수정:
  고리별 독립 교대가 아니라 aromatic component 전체의 matching으로
  동등한 Kekulé 표현을 생성하고 원본 identity를 검증한다.
  반드시 표현 선택 → clean target 확정 → corruption 순서로 적용한다.
  train1264개에서 총4414개 표현, 995개에 복수 표현, identity mismatch0.
  특수 component1건은 원본 유지. val/test 증강은 하지 않는다.
판정:
  [수정·검증] 4414개의 새로운 분자/물성 label을 추가한 것이 아니다.

6.3. final decoding의 원자·결합·연결성 공동 결정
수정:
  final endpoint에 선택적으로 joint MAP/MILP decoder를 연결했다.
  atom-state/허용 heavy valence/bond order/count/net charge/connectivity를
  하나의 제약 문제에서 선택한 뒤 RDKit 검사한다.
  중간 reverse state는 변경하지 않으며 raw와 projected 결과를 분리 저장한다.
판정:
  [구현·oracle 검증/성능 미확정] constrained MAP이지 원래 분포의 unbiased sample이 아니다.
  time limit·support 밖 state·geometry·물성 문제는 남는다.
  pure codec1581/1581과 train-supported solver oracle1580/1580을 구분한다.
  held-out-only Si-H state1건은 decode 가능하지만 생성 support에 넣지 않았다.

6.4. self-conditioning과 off-path correction의 불일치
수정:
  이전 endpoint를 detached history로 넣고, CFG conditional/unconditional
  history를 분리했다. chemistry feedback의 마지막 linear는 0 초기화한다.
  correction은 별도 objective로 지연 시작·ramp·확률0.25·weight0.02,
  geometry noise0.05 Å, node/edge replacement0, weighted loss10% 상한을 둔다.
판정:
  [구현 검증/잔존] loss 상한이지 gradient norm/방향 상한이 아니다.
  correction이 항상 성능을 올린다는 근거는 없다.

6.5. clean atom count가 주어진 것과 자유로운 count 생성의 혼동
수정:
  train-only P(n|condition), 최대30% FAKE-node capacity 및 deletion을 도입했다.
  FAKE는 학습 대상 state이고 MASK는 미지 상태이며 padding과 다르다.
판정:
  [부분 개선] count 자유도는 생겼지만 requested count의 정확한 실현은 아니다.
  e3911에서 요청 count와 정확히 같은 raw 표본은144/1000이다.
  임의50원자 등 학습 support 밖 크기를 지정해도 안정적 생성이 보장되지 않는다.

6.6. independent-time 학습과 실제 reverse schedule의 차이
수정:
  좌표/graph time을 별도로 입력하고 각 feature의 schedule/loss와 연결했다.
  50% graph-clean branch를 추가하고 bond-first coordinate update를 도입했다.
판정:
  [계약 명확화/잔존] production sampling은 여전히 t_x=t_graph 대각 경로다.
  '먼저 완성 graph를 만든 뒤 좌표 생성'하는 2D reverse solver가 아니다.
  graph-clean branch는 보조 복원 학습이며 그 효과는 실증해야 한다.

6.7. 회전 검사만 통과하고 반사 계약은 어긋남
문제:
  Kabsch는 reflection을 허용했지만 GVP cross-product feature는 parity에 민감했다.
수정:
  현재 non-stereo 모델은 n_cp_feats=0의 O(3) 계약을 선택했고,
  Kabsch 중심 복원식과 다층 field의 반사·회전·평행이동 검사를 맞췄다.
판정:
  [수정·검증] chirality/E-Z 생성 기능을 추가한 것이 아니다.

6.8. 검증 loss가 무작위 noise/dropout에 흔들림
수정:
  validation 고정 time grid와 고정 corruption RNG,
  validation의 CFG/hidden dropout 비활성화,
  같은 corruption에서 condition shuffle 비교를 도입했다.
  raw validity/connectedness/neutral-closed-shell/geometry 등을 별도 기록한다.
판정:
  [수정·검증/잔존] 고정-grid validation은 확률적 train loss와 같은 estimator가 아니다.
  이번 e3911은 best validation checkpoint이지 모든 생성 지표의 최선이라는 뜻이 아니다.


7. 장기학습·재개·운영에서 실제 발생한 문제
========================================

7.1. Stage8 nonfinite gradient로 학습 중단
현상:
  최초 Stage8 run에서 property_embedder.0.weight의 nonfinite gradient가 탐지돼 중단됐다.
원인 및 수정:
  edge-existence loss에서 FP32의 1-eps가1로 반올림되고 p(edge)가1이 되면
  log1p(-1)가 발생했다. torch.where의 선택되지 않은 branch도 계산되어
  backward에 NaN을 만들 수 있었다.
  log_softmax/logsumexp로 같은 clipped likelihood를 log-space에서 계산하도록 바꿨다.
  포화 logit, inactive edge, 오답 확률 floor의 finite gradient 회귀 검사를 추가했다.
판정:
  [수정·검증] 오류가 처음 보고된 parameter가 근본 원인이라는 뜻은 아니다.
  e476 checkpoint에서 수정 코드를 사용해 재개했고 후속 수천 epoch가 진행됐다.

7.2. checkpoint 재개와 last.ckpt의 의미
문제:
  이전 Stage6 last.ckpt가 최종 logged epoch가 아니라 top-k에 들어간 과거 epoch였다.
  Stage8 재개1차는 weights-only deserialization에서 PosixPath 때문에 실패했다.
  2차는 resume 직후 TrainingStatus.step_losses 초기화 누락으로 실패했다.
수정:
  신뢰 가능한 자체 checkpoint에 한해 full trainer state를 로드하도록 명시했다.
  callback state의 초기화/재개를 보완하고, best와 매 epoch last 저장을 분리했다.
  val이 악화해도 last epoch가 전진하고 optimizer state/step이 복원되는 테스트를 추가했다.
판정:
  [수정·검증] 최종 v3 run이 정상 재개됐다. 실패한 v1/v2 폴더는 보존했다.

7.3. batch를 키웠지만 OOM·fragmentation과 크기별 비용을 놓침
문제:
  complete graph는 N(N-1) edge를 사용하므로 molecule batch 수만으로
  메모리를 예측할 수 없다. 과거 max_num_edges 설정이 loader에 연결되지 않기도 했다.
수정:
  실제 FAKE capacity까지 포함한 directed-edge budget sampler,
  최대 batch128/edge40000, coverage 검증, 일정 epoch batch 수,
  largest-batch optimizer capacity probe와 expandable_segments를 적용했다.
판정:
  [수정·검증/잔존] GPU allocator 상한70%는 실제 메모리나 연산점유70%가 아니다.
  STGG의 큰 분자는 실제 batch가 작아지고 epoch당 step이 많아진다.
  epoch 수만으로 HP1KG와 STGG의 학습량·속도를 비교하면 안 된다.

7.4. 생성 정체와 학습·생성 동시 자원 경쟁
문제:
  과거 생성이 장시간 첫 chunk도 끝내지 못했고, GPU 경쟁 외에도
  projection/search/CPU 후처리 병목을 구분하기 어려웠다.
수정:
  batch/단계별 timing, raw endpoint 저장, status/log/manifest,
  작은 generation batch, solver 시간 상한 및 독립 CPU 작업을 추가했다.
판정:
  [운영 개선] GPU 메모리가 남아도 연산이 병목일 수 있다.
  모든 느린 원인을 GPU 하나로 단정하지 않는다.

7.5. 세션 종료 시 작업 지속과 실험 보존
수정:
  start_new_session, stdin=/dev/null, 파일 stdout/stderr,
  PPID1·독립 SID 확인, 새 output directory, checkpoint snapshot/hash,
  raw 실패 ledger까지 보존하는 방식을 사용한다.
판정:
  [운영 검증] 학습·생성·XTB가 대화 세션 종료를 기다리는 구조가 아니다.
  서버 종료·프로세스 오류·리소스 회수까지 막는 것은 아니다.


8. 생성 후 평가·XTB/STDA 파이프라인에서 수정한 문제
=================================================

8.1. RDKit ETKDG 재생성이 diffusion 좌표 평가를 대체함
문제:
  과거 후처리 중 SMILES→ETKDG→MMFF/UFF로 새 좌표를 만든 결과를
  diffusion 자체의 3D 생성 능력처럼 읽을 위험이 있었다.
수정:
  현재는 saved endpoint의 atom state/bond/XYZ로 동일 graph를 재구성하고,
  RDKit AddHs(addCoords=True)로 H 좌표만 추가한 뒤 XTB를 시작한다.
  H 추가 전후 heavy XYZ 최대 차이0 Å, identity round-trip을 검증한다.
  aromatic heavy-only SDF 재독해의 H 손실을 피하려고 H 추가 후 Kekulé SDF를 저장한다.
판정:
  [수정·검증] XTB 최적화 후에는 원자가 이동할 수 있다.
  heavy 좌표 보존은 XTB 입력 단계에 대한 주장이다.

8.2. 계산 성공을 구조·물성 성공으로 과대평가
수정:
  invalid/disconnected/open-shell/nonzero-charge/preparation/calculation failure를
  전체1000개 outcome ledger에 유지한다. 계산 대상 중 성공률과 전체 yield를 구분한다.
  최적화 RMSD, aromatic plane, bond WBO, 새 heavy contact/H transfer를 별도 분석한다.
남은 한계:
  이전 e1321 계산에서도 최적화 후 H transfer와 새 결합 후보가 확인됐다.
  2D PNG의 원본 graph가 최적화 후 동일 protonation/connectivity라는 보장은 없다.
  Hessian/minimum 확인·합성 가능성·고수준 excited-state 검증은 별도다.

8.3. 서로 다른 조건을 잘못 집계할 위험
수정:
  최신 실행기를 EST 전용에서 manifest 기반 EST 또는 S1 단일 조건으로 확장했다.
  HP1KG는 EST0, STGG는 S1=4.0으로 평가하며 없는 T1/EST target을 만들지 않는다.
  다른 target을 CLI로 넣으면 거부한다. 5개 회귀 테스트를 통과했다.
  sTDA 출력의 decimal 에너지로 경계 hit를 집계한다.
  e1321 |EST|<0.1은49개, |EST|<=0.1은52개다. 과거 float 집계50과 구분한다.
판정:
  [수정·검증] 계산 수준 보정은 이번 결과에 적용하지 않았다.
  과거 DB↔XTB 보정 실험이 존재한다는 사실과 이번 결과의 보정 적용 여부는 별개다.

10. 현재 남은 핵심 문제와 다음 판단 기준
======================================

1) atom/H/charge/bond의 전역 discrete consistency는 완전 해결되지 않았다.
   H를 넣고 평균/분포 loss를 추가했어도 radical·valence 오류가 남는다.
2) 다각고리 전체가 해결된 것이 아니다. e3911에서는 큰 고리는 줄었지만
   3·4원 고리 포함 사례가 늘었다. 원소 조성·공유 원자·bridgehead도 같이 봐야 한다.
3) 물성 조건 민감도와 목표 달성률은 다르다. 계산 가능한 subset에 대한
   평균 오차뿐 아니라 전체1000개 기준 '정상 방향족+near-zero' yield가 필요하다.
4) 공식 XYZ의61 H mismatch/6 edge 예외는 다운로드 오류가 아니라
   graph-geometry 정의 차이로 남는다. codec100%로 덮을 수 없다.
5) 작은 HP1KG train1264개에서 과적합·희소 조건·원소별 희소성은 남는다.
   데이터 확대 없이도 개선은 시도할 수 있지만 새 loss 추가만으로 해소되지 않는다.
6) 모든 변경을 한꺼번에 넣으면 원인 귀속이 어렵다. 동일 seed/count/step 예산,
   raw/solver 분리, 여러 training seed, 계산 수준을 고정한 ablation이 필요하다.
7) 지금까지의 테스트는 알려진 반례와 계약의 검사다. 모든 가능한 분자·입력의
   논리/수학적 무결성에 대한 형식 증명은 아니다.

현재 결론:
  구조 표현·수소·인덱스·좌표 출처·손실 reduction·EMA/offset·수치 안정성·
  checkpoint/자원/평가 계약은 이전보다 명확해졌다.
  그러나 구조의 전역 일관성과 조건을 만족하는 실제 분자의 충분한 생성률은
  여전히 미해결이다. '코드 수정 완료'와 '연구 성능 목표 달성'을 구분해야 한다.


11. 왜 같은 유형의 문제가 다시 발견됐는가
=======================================

- 브랜치/아키텍처가 바뀌며 이전 수정이 새 구현에 빠지거나 의미가 달라졌다.
- codec oracle, untrained smoke, gradient finite 검사만으로 장기 rollout을
  판단한 경우가 있었다. stage별 검증 범위가 서로 달랐다.
- graph adjacency만 비교하고 H/charge/aromatic identity를 검사하지 않은 검증은
  분자 보존을 충분히 확인하지 못했다.
- 평균 chemistry loss는 실제 discrete 표본의 joint validity를 검사하지 못한다.
- 학습·생성·후처리·평가가 다른 schema나 source snapshot을 쓰는 경로가 있었다.
- batch/molecule/edge/masked-item 분모와 loss 정의가 바뀌어 수치 비교가 왜곡됐다.
- raw, projected, largest-fragment, RDKit valid, XTB-eligible을 섞으면
  성공률을 실제보다 좋게 해석하게 된다.

현재의 대응은 전체 pipeline identity/manifest, 반례 회귀 테스트, 실제 optimizer
및 다단계 sampling 검사, raw 실패 보존, 독립 물성 계산으로 검증 층을 분리하는 것이다.
